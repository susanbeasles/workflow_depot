# Existing App dispatch boundary

The new reusable source replaces a stored dispatch-token dependency with a short-lived existing GitHub App installation token. Commissioning defaults false and no identity is guessed. Required nonsecret operator inputs are the existing App numeric ID, client ID, slug, delivery_control installation ID, exact op://vault-ID/item-ID/field reference for its RSA private key, and a scoped approval reference. The existing scoped OP_SERVICE_ACCOUNT_TOKEN is the only bootstrap; no key is placed in GitHub variables/secrets, files or logs by the adapter.

When separately commissioned, public App identity/Actions-write capability are checked before official CLI key access. JWT identity and installation ownership are checked, a token is requested for only repository ID 1405415291 with Actions write, returned permissions/expiry and exact accessible repository are verified, one fixed dispatch is performed, and the token is revoked. Extra permissions, mismatched identities, missing input or ambiguous outcomes fail closed; no PAT, Cloudflare credential, SDK/Connect path or automatic retry exists.

No live App token/JWT was generated during implementation. Tests use synthetic local RSA material and mocked APIs. Current metadata reads for RELEASE_APP_CLIENT_ID and secret names are Forbidden; the accessible matching 1Password item is an SSH signing item, not a verified GitHub App credential. These cannot be repurposed. The actual required identity/item values remain unknown and must be identified with metadata-only access and separately approved before configuring this path.

## Trusted reusable source revision

Deployment request callers must grant `contents: read` and `id-token: write` to the reusable workflow call, including every enclosing reusable-workflow call. `main-deployment.yml` delegates this permission to its dispatch call. The checkout-free source-resolution job alone requests OIDC to obtain GitHub’s `job_workflow_sha`; dispatch jobs retain only `contents: read`. The resolver checks the fixed depot repository, exact reusable workflow path, current run identity, and freshness before returning only the callee SHA. Caller `depot_ref` must equal that SHA; mismatches fail closed. No deployment credential enters the resolver. The outer caller must pin the reviewed workflow revision; this check binds executable source to that revision and does not independently approve arbitrary revisions.

Caller commissioning flags and approval strings confer no authority. Before any API operation or private-key lookup, the adapter requires an exact reviewed source enrollment binding approval reference, App ID/client ID/slug, installation ID, private-key item field reference, caller repository name/ID and deployment target. `ci/trusted-admission.mjs` intentionally has no enrollments. Existing operator-approved identities must be independently verified and added through source review before activation. No existing key or endpoint was inferred.
