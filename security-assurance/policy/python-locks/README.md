# Python tool artifact locks

These candidate locks were generated from actual public PyPI wheels for the exact `python_tools` versions in `tool-registry.yml`, using Linux x86_64 CPython 3.12 (the ubuntu-24.04 analysis runner). Every wheel hash and byte size was checked against its public PyPI version JSON before inclusion. `artifacts.json` records filenames, versions, groups, SHA256, sizes and official source URLs. No hashes or transitive versions are placeholders. Source review approves these candidate inputs together with the code; generation is not a claim of independent approval.

The Semgrep, Checkov, Hypothesis and Schemathesis locks each contain their complete resolved closure. Bandit and pip-audit share one compatible combined closure because the ecosystem action runs them together. Semgrep and Checkov use separate virtual environments because their selected dependency pins conflict. Pip's offline `--dry-run --ignore-installed --require-hashes` resolution passed for all six locks, and all five isolated installation groups passed `pip check`. No scanner was invoked for this material validation.

The installer accepts only exact registry tool versions, exact transitive pins and SHA256 hashes. A supplied controlled wheelhouse is consumed offline. Otherwise the CLI downloads only the hash-locked wheels from public PyPI with keyring, user configuration and package index overrides disabled, then installs offline with `--no-deps --require-hashes --no-index --only-binary=:all:` in a fresh virtual environment. Dependency closure must pass `pip check`. No sdist build or package lifecycle hook is used. Download/install errors remain control failures. Unsupported platforms without a matching pinned artifact fail; do not invent a substitute hash or remove the hash gate.

To update, use the standard configured package route and exact registry tool versions with `pip download --only-binary=:all:` into a clean directory, verify every resulting wheel against PyPI's filename/SHA256/size metadata, regenerate the complete lock plus provenance, and repeat offline resolution and isolated installation checks. Never use candidate package-manager configuration or credentials. Refresh the explicit local hardening hashes without changing the original import manifest. Hosted scanner/runtime/Swift qualification and commissioning are separate from dependency material validation.
